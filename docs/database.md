# בסיס הנתונים

Cloudflare D1 (SQLite). 44 טבלאות ועוד טבלת FTS5 וירטואלית, בתשע מיגרציות.

| מיגרציה                  | תחום                                                                       |
| ------------------------ | -------------------------------------------------------------------------- |
| `0001_catalog`           | קטגוריות, ערוצים, סרטונים, תגיות, יצרנים ודגמים, FTS5, מילים נרדפות, מונים |
| `0002_users_and_access`  | משתמשים, roles, sessions, העדפות, רכבי המשתמש                              |
| `0003_library`           | מועדפים, פלייליסטים, היסטוריה, חיפושים שמורים, מעקב ערוצים                 |
| `0004_engagement`        | דיווחים, הערות, הצעות, פניות, rate limits, לוג חיפושים                     |
| `0005_admin`             | audit log, ייבוא, אוספים, מקטעי דף הבית, feature flags, מכסות              |
| `0006_oauth`             | חשבונות Google, מיזוג ספרייה ממכשיר                                        |
| `0007_maintenance`       | בדיקת קישורים מתוזמנת, יומן ריצות                                          |
| `0008_counters`          | מונים מתוחזקים, מדיניות שמירה, מדגמי גדילה                                 |
| `0009_search_log_rollup` | סיכום יומי של לוג החיפושים, תור בדיקת הקישורים                             |

## מוסכמות

- `snake_case`, מפתח `id`.
- זמנים: TEXT ב-ISO-8601 UTC.
- בוליאנים: INTEGER 0/1 עם `CHECK`.
- לכל מפתח זר יש `ON DELETE` מפורש.
- מחיקה רכה בלבד (`deleted_at`). האפליקציה לא מוחקת שורות.

## החלטות

### המפתח של `videos` הוא מזהה ה-YouTube

זה המפתח הטבעי: הוא מה שבודקים מולו כפילות, הוא מה שנמצא בכתובת, והוא מונע
מצב שבו אותו סרטון קיים פעמיים תחת שני מספרים רצים.

### ערוצים מנורמלים

בקטלוג הישן שם הערוץ והאווטר חזרו על עצמם בכל שורה — 409 ערוצים על פני 7,876
סרטונים. הנרמול הוא מה שמאפשר דף ערוץ, "עוד מהערוץ" ותיקון שם במקום אחד.

### FTS5 עצמאי, לא external content

המסמך המאונדקס הוא **join**: כותרת + תיאור + שם ערוץ + תגיות + יצרן + דגם.
טריגר על `videos` לבדה לא יכול להרכיב את זה. לכן `videos_fts` מתוחזק מפורשות
בשכבת ה-repository, וייבוא הקטלוג בונה אותו מחדש.

טוקנייזר: `unicode61 remove_diacritics 2` — תואם ל-`indexText` בצד הקוד.

### מונים בטבלה נפרדת

`video_stats` נפרדת מ-`videos` כדי שעדכון מונה צפיות לא יגע בשורה שנמצאת במטמון
ולא יגרום ל-`updated_at` לקפוץ. גם ככה אין כתיבה על כל צפייה — היא מרוכזת.

### rate limits כחלון קבוע

שורה אחת לכל (fingerprint, פעולה, חלון), upsert אחד לכל בקשת כתיבה, אפס עבודה
בקריאות. פחות מדויק מחלון נע, ובהרבה יותר זול.

### `home_sections` בטבלה

דף הבית הוא רשימת שורות מהטבלה הזו. שינוי סדר, הוספת "סקירות בטיחות חדשות"
או הסתרת מקטע — פעולה בממשק הניהול, לא פריסה.

### לוג חיפושים אנונימי

`search_logs` שומרת את הטקסט המנורמל, את הטקסט כפי שנכתב ואת מספר התוצאות.
בלי משתמש, בלי IP. הדוח שמעניין הוא זה: _27 אנשים חיפשו "החלפת משאבת ABS"
ולא מצאו כלום_ — זו רשימת המשימות של העורך.

### מונים מתוחזקים במקום ספירה בזמן קריאה

זו ההחלטה שהכי משנה את עלות ההרצה, והיא נולדה ממדידה: `/api/tags` ענה על
"אילו תגיות פופולריות?" בעזרת join של 7,876 סרטונים חיים ל-59,255 שורות
`video_tags` — כ-127,000 שורות נקראות **לכל בקשה**, לשאלה שהתשובה שלה משתנה רק
כשעורך משנה משהו. במכסה של 5,000,000 שורות ליום, 39 בקשות ל-endpoint הזה היו
מסיימות את התקציב היומי.

לכן כל מספר שמבקר רואה אבל רק עורך יכול לשנות הוא עמודה שמורה:
`categories.video_count`, `channels.video_count`, `tags.video_count`,
טבלת `category_tag_counts` לפאנל הסינון, ו-`catalog_counters` למונים הכלליים.
`CountersRepository` הוא הבעלים היחיד שלהן — אף אחד אחר לא כותב לשם, כך שיש מקום
אחד להסתכל בו כשמספר שגוי.

התמורה היא פיגור של עד שעה, וזו עסקה משתלמת: שבב קטגוריה שכתוב בו 820 במקום 821
אינו פגם שמישהו יכול להבחין בו. **הנכונות שכן חשובה — אילו סרטונים רשימה
מחזירה — עדיין מגיעה מהטבלאות החיות בכל בקשה.**

זה גם לא מטמון שיכול להירקב בשקט: `catalog_counters.updated_at` מוצג בלוח
הניהול, ומשימת cron שנעצרה מופיעה כאזהרה במקום פשוט להיות שגויה.

### מדיניות שמירה

הקטלוג כולו הוא 18 MiB מתוך 500 MB, כך שהסיכון לנפח אינו הקטלוג אלא הטבלאות
שגדלות עם התנועה. לכל אחת מהן יש שני חסמים ב-`RETENTION` — גיל ותקרת שורות —
ומשימת התחזוקה מיישמת אותם. `table_growth_samples` שומרת ספירת שורות יומית לכל
טבלה, וזה מה שמאפשר תחזית: _בקצב הזה, מתי נגיע ל-500 MB?_

הפירוט: [`performance.md`](performance.md).

## שינוי סכימה

מיגרציה חדשה בלבד. לעולם לא לערוך קובץ קיים — הוא כבר רץ אצל מישהו.

```bash
# migrations/0010_<שם>.sql
npm run db:migrate:local
npm test          # הבדיקות מריצות את כל המיגרציות מאפס בכל ריצה
```

הבדיקות הן מה שמאמת את הסכימה: `tests/helpers/d1.ts` בונה בסיס נתונים בזיכרון
מהמיגרציות האמיתיות, כך ש-SQL שגוי נופל בבדיקה ולא בפרודקשן.
